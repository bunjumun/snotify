The point

A local 4B model is far too slow and too weak to write your code. It generates at 6 to 10 tokens a second. If this pitch were about moving the building onto your laptop, it would be a pitch against.

But it is not slow at deciding. Deciding costs five tokens. And deciding is what 149 of your 153 runs were doing.

The proposal

A gate, not a replacement

The local model gets exactly one job and no others. It never writes code, never touches the note, never picks what to build, never talks to the database. It reads two things and says one word.

Before each hourly run: hash the note and the git head, hand the model the old BUGS and QUEUE against the new, ask CHANGED or UNCHANGED. On UNCHANGED, the paid run never starts. On CHANGED, everything proceeds exactly as it does today.

Ollama has enforced JSON since 0.3.0, so the answer is constrained at the token level rather than parsed hopefully out of prose. A malformed reply is mechanically impossible, and anything unexpected falls through to running the paid pass. The gate fails open, always.

Putting it on a second machine settles the worst of this

This was pitched to run on the M1, and the honest catch was that staying at 1.25 seconds meant holding 3.3 GB of your 16 GB permanently. You asked for a separate machine instead. That removes the catch entirely, and buys three things beyond it:

The 42 second cold load happens once at boot rather than on an hourly gamble, because nothing else on that box competes for its memory. This Mac keeps all 16 GB while you work. And the model ceiling stops being 4B: on a dedicated box a 7B or 8B fits, which is meaningfully more reliable on exactly the subtle changes the small model is unproven on.

What it still costs you

  • A machine that stays on. An old Mac, a Linux box, a NUC, or a 16 GB Pi all clear the bar. It needs a reserved IP so the address does not move, and it must stay awake.
  • One new failure mode: the host can be unreachable. Handled by failing open. Host down, timeout, odd reply, anything that is not a confident UNCHANGED runs the paid pass exactly as today. The gate can only save money, never lose work.
  • A missed change costs an hour. If the model wrongly says UNCHANGED, work waits for the next run. Capped by one unconditional full run a day.
  • Untested on subtle edits. It caught an obvious new bug line three times out of three. I have not proven it catches you quietly reordering two QUEUE lines, which is why the plan dry-runs it for a few days before it is allowed to skip anything.
